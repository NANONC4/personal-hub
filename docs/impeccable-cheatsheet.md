# Impeccable — สรุปคำสั่งทั้งหมด (ภาษาคน)

Impeccable คือ skill ที่ติดตั้งไว้ใน Claude Code สำหรับงาน **ออกแบบหน้าเว็บ / UI**
ไม่ใช่สำหรับงาน backend หรืองานที่ไม่เกี่ยวกับหน้าตา

เรียกใช้แบบ: `/impeccable <คำสั่ง> [เป้าหมาย]`
ตัวอย่าง: `/impeccable critique หน้าแรก` · `/impeccable polish components/Footer.tsx`

พิมพ์ `/impeccable` เฉยๆ ไม่ใส่คำสั่ง = มันจะขึ้นเมนูให้เลือก

---

## 🟢 เริ่มต้น / เก็บข้อมูล (Build)

| คำสั่ง | ทำอะไร | ใช้ตอนไหน |
|---|---|---|
| **`init`** | สัมภาษณ์เราแล้วเขียน **PRODUCT.md** — เว็บนี้ทำเพื่อใคร เป้าหมายคืออะไร อะไรของจริงอะไรของปลอม | ครั้งแรกของโปรเจกต์ หรือตอนข้อมูลเก่าไม่ตรงแล้ว |
| **`document`** | อ่านโค้ดที่มีอยู่ แล้วเขียน **DESIGN.md** — สี ฟอนต์ ระยะห่าง เงา component ที่ใช้จริง | มีเว็บอยู่แล้วแต่ยังไม่มีเอกสารดีไซน์ |
| **`shape [ฟีเจอร์]`** | วางแผน UX/UI **ก่อนเขียนโค้ด** — คุยจนได้ brief ที่ชัด ยังไม่ลงมือทำ | จะทำหน้าใหม่/ฟีเจอร์ใหม่ แต่ยังไม่แน่ใจว่าหน้าตาควรเป็นยังไง |
| **`extract [เป้าหมาย]`** | ดึงสี/ค่า/component ที่ใช้ซ้ำๆ ออกมาเป็น design system | โค้ดเริ่มมีค่าซ้ำกระจัดกระจาย อยากรวบให้เป็นระบบ |

> ✅ **โปรเจกต์นี้ทำไปแล้ว:** `init` → [PRODUCT.md](../PRODUCT.md) · `document` → [DESIGN.md](../DESIGN.md) + `.impeccable/design.json`

## 🔍 ตรวจสอบ (Evaluate)

| คำสั่ง | ทำอะไร | ใช้ตอนไหน |
|---|---|---|
| **`critique [เป้าหมาย]`** | **ตรวจใหญ่** — แยก AI 2 ตัวทำงานอิสระ (ตัวนึงดูดีไซน์ ตัวนึงสแกนโค้ด+เปิดเบราว์เซอร์จริง) แล้วรวมผล ให้คะแนน 40 เต็ม + ลิสต์ปัญหาเรียงความสำคัญ + เช็คผ่านมุมมองคนใช้ 3-4 แบบ | อยากรู้ว่าเว็บมีปัญหาอะไรบ้าง แบบครบทุกมุม |
| **`audit [เป้าหมาย]`** | ตรวจ**ด้านเทคนิค** — accessibility, ความเร็ว, การแสดงผลบนจอต่างๆ | อยากรู้ว่ามีปัญหาทางเทคนิคตรงไหน (แคบกว่า critique แต่ลึกกว่าในด้านนี้) |

> ✅ **ทำไปแล้ว:** `critique` ทั้งเว็บ → ได้ 19/40 · รายงานเก็บที่ `.impeccable/critique/`

## 🔧 ขัดเกลาของที่มีอยู่ (Refine)

| คำสั่ง | ทำอะไร | ใช้ตอนไหน |
|---|---|---|
| **`polish [เป้าหมาย]`** | เก็บงานรอบสุดท้ายก่อนปล่อยจริง — รายละเอียดเล็กๆ ที่ทำให้ดูโปร | ทุกอย่างเสร็จแล้ว อยากเก็บให้เนียน |
| **`bolder [เป้าหมาย]`** | ทำให้**กล้าขึ้น** เด่นขึ้น | หน้าตาดูจืด ปลอดภัยเกินไป ไม่มีจุดจำ |
| **`quieter [เป้าหมาย]`** | ทำให้**เบาลง** สงบลง | รกตา สีเยอะ อนิเมชันเยอะ ล้าตา |
| **`distill [เป้าหมาย]`** | **ตัดให้เหลือแก่น** เอาของที่ไม่จำเป็นออก | มีของเยอะเกิน ซับซ้อนเกิน |
| **`harden [เป้าหมาย]`** | ทำให้**พร้อมใช้จริง** — จัดการ error, ข้อความหลายภาษา, เคสแปลกๆ | ก่อนปล่อยให้คนใช้จริง |
| **`onboard [เป้าหมาย]`** | ออกแบบ**หน้าแรกที่คนเจอ** — first-run, หน้าว่างเปล่า (empty state) | คนเข้ามาแล้วไม่รู้จะทำอะไรต่อ |

> ✅ **ทำไปแล้ว:** `quieter` → ลดไฟกะพริบในหน้าต่าง + ลดหิ่งห้อยหลัง hero

## ✨ เพิ่มของ (Enhance)

| คำสั่ง | ทำอะไร | ใช้ตอนไหน |
|---|---|---|
| **`animate [เป้าหมาย]`** | เพิ่มอนิเมชันที่**มีเหตุผล** ไม่ใช่ใส่มั่ว | อยากให้มีชีวิตขึ้น แต่ไม่รกตา |
| **`colorize [เป้าหมาย]`** | เพิ่มสีอย่าง**มีกลยุทธ์** | หน้าตาขาวดำ/จืดเกินไป |
| **`typeset [เป้าหมาย]`** | จัด**ตัวอักษร** — ลำดับความสำคัญ ขนาด ฟอนต์ | ข้อความดูแบนๆ ไม่รู้อะไรสำคัญกว่า |
| **`layout [เป้าหมาย]`** | จัด**ระยะห่างและการวาง** ให้มีจังหวะ | ช่องไฟมั่ว ไม่เป็นระเบียบ |
| **`delight [เป้าหมาย]`** | เพิ่ม**ลูกเล่นน่ารักๆ** ที่คนจำได้ | อยากให้มีเสน่ห์ มีอะไรให้เซอร์ไพรส์ |
| **`overdrive [เป้าหมาย]`** | **ดันสุดขีด** เกินกว่าที่คนทั่วไปกล้าทำ | อยากให้ว้าวไปเลย ไม่กลัวแรง |

## 🩹 แก้ปัญหาเฉพาะจุด (Fix)

| คำสั่ง | ทำอะไร | ใช้ตอนไหน |
|---|---|---|
| **`clarify [เป้าหมาย]`** | แก้**ข้อความ** — ป้ายปุ่ม, ข้อความ error ให้เข้าใจง่าย | คำในเว็บงงๆ กำกวม |
| **`adapt [เป้าหมาย]`** | แก้ให้แสดงผลดีบน**จอทุกขนาด** | มือถือพัง / จอใหญ่โล่ง |
| **`optimize [เป้าหมาย]`** | หาสาเหตุและแก้**ความอืด** | เว็บกระตุก โหลดช้า |

## 💡 แนวคิดที่มันใช้ตัดสินใจ

มันจะดูก่อนว่าหน้าที่กำลังทำเป็น**โหมดไหน** แล้วให้น้ำหนักต่างกัน:

| โหมด | คนเข้ามาทำอะไร | ตัวอย่าง |
|---|---|---|
| **Persuade** | มาตัดสินใจ/ซื้อ — ดีไซน์คือตัวสินค้า | หน้า landing, หน้าราคา |
| **Operate** | มาทำงานให้เสร็จ — ใช้ง่ายสำคัญกว่าสวย | dashboard, หน้า settings |
| **Read** | มาอ่านเพื่อเข้าใจ — จัดโครงให้อ่านง่าย | บทความ, เอกสาร |
| **Experience** | มาดูงาน — ให้ผลงานนำ UI หลบ | **พอร์ตโฟลิโอ ← เว็บเรา** |

## ⚠️ ข้อควรรู้

- **มันจะถามก่อนเสมอ** ถ้าเรื่องนั้นตัดสินใจแทนเราไม่ได้ (เช่น "เว็บนี้ทำเพื่อใคร") — ตอบตามจริง อย่าปล่อยให้มันเดา
- **บอกได้ว่าอะไรตั้งใจ** ถ้ามันชี้ว่าเป็นปัญหาแต่จริงๆ เราตั้งใจ ให้บอกไป มันจะไปบันทึกลง DESIGN.md ว่าเป็นข้อยกเว้น ครั้งหน้าจะไม่มาแก้กลับ *(เช่น `/bio` พื้นสว่าง, `/contact` สีเหลือง)*
- **`critique` กินเวลานาน** เพราะแยก AI 2 ตัวทำงานจริง + เปิดเบราว์เซอร์สแกน อย่ารันบ่อย
- **มันยึด DESIGN.md เป็นกฎ** ถ้าเปลี่ยนใจเรื่องสี/ฟอนต์ ควรอัปเดต DESIGN.md ด้วย ไม่งั้นงานต่อไปจะถูกดึงกลับไปตามเอกสารเก่า

## 🗺️ ลำดับที่แนะนำ ถ้าเริ่มโปรเจกต์ใหม่

```
1. /impeccable init        → เก็บข้อมูลโปรเจกต์
2. /impeccable shape <หน้า> → วางแผนก่อนทำ
3.  (ลงมือเขียนโค้ด)
4. /impeccable document    → บันทึกระบบดีไซน์ที่ได้
5. /impeccable critique    → ตรวจว่ามีปัญหาอะไร
6. /impeccable <แก้ตามผล>  → quieter / adapt / harden / ...
7. /impeccable polish      → เก็บงานก่อนปล่อย
```

โปรเจกต์นี้ตอนนี้อยู่ขั้น **6** — critique แล้ว แก้ไปแล้วเกือบหมด เหลือ `polish` รอบสุดท้าย
